## Build/Test commands
- Любые команды, которые могут генерировать большой вывод и расходовать много токенов, запускать только по прямому запросу пользователя.
- Не запускать `npm run build`, `npm run lint`, `npm test`, `vitest`, `jest` и другие тяжелые проверки без явной просьбы пользователя.
- По умолчанию не выполнять сборку, линт и тесты после изменений.
- Если проверка действительно нужна, сначала спросить пользователя.
- Когда делаешь правки в коде — смотри `/docs`, там есть `backlog.md`.

## Деплой на VPS и миграции Prisma

`deploy.sh` **не** запускает Prisma-миграции. После успешного `./deploy.sh staging` (или push в `staging`):

1. Проверь, появились ли **новые** папки в `backend/prisma/migrations/`, которых ещё нет в `_prisma_migrations` на VPS (например, сравни с предыдущим деплоем / смотри diff ветки).
2. **Если есть новые миграции** — примени их на VPS отдельно:
   ```bash
   docker exec antiquar-backend npx prisma migrate deploy
   ```
   На проде только **`prisma migrate deploy`**. Не используй `prisma migrate dev` на production.
3. **Если новых миграций нет** — ничего с БД делать не нужно.

Локально для той же команды: `make prisma-deploy`.
