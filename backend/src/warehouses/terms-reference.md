# Техническое задание (TЗ) проекта «Склад»

Документ фиксирует текущее состояние системы и формирует ориентиры для дальнейшей разработки: цели, архитектуру, реализованные модули, интерфейсы и план доработок.

## Цель проекта
- Вести учёт товаров: остатки, перемещения, продажи, возвраты.
- Обеспечить роли и права: продавец, менеджер, администратор.
- Предоставить удобный web‑интерфейс для ежедневной работы и управленческой отчетности.

## Архитектура
- Backend: NestJS (controllers/services/modules), Prisma (PostgreSQL/MySQL, в зависимости от окружения), MinIO для хранения изображений, JWT аутентификация, аудит операций.
- Frontend: Vue 3 + Vite, PrimeVue компоненты, Pinia (хранилище состояния), Vue Router, Vitest для тестов.
- Инфраструктура:
  - Валидация запросов (ValidationPipe, DTO).
  - Заголовки безопасности (helmet), CORS.
  - Статическая отдача загруженных файлов `/uploads`.

## Backend: модули и ответственность
- Auth: регистрация, вход, `GET /auth/me` (возвращает текущего пользователя).
- Users: управление пользователями и ролями; доступ ограничен.
- Products: CRUD товаров, загрузка изображений, фильтрация и пагинация, связь с категориями/складами/комитетами.
- Categories: справочник категорий.
- Warehouses: справочник складов, публичный просмотр списка и деталей.
- Committees: справочник комитетов.
- Sales: операции продажи, изменение остатков, аудит.
- Returns: операции возврата, пересчет остатков, аудит.
- Transaction Types: справочник типов транзакций (операционные типы, используемые в продажах/возвратах).
- User Statuses: справочник статусов пользователей.
- Audit Log: журнал действий (кто/когда/откуда и какие поля изменились).
- MinIO: сервис загрузки/хранения/ссылок на файлы.
- Prisma: подключение к БД, модели, миграции, seed‑данные.

## Backend: безопасность и доступ
- JWTGuard как глобальный guard, `@Roles` и `RolesGuard` для ролевого доступа.
- Публичные эндпоинты: корень приложения (`/`), список складов и детали склада.
- Валидация DTO: удаление лишних полей (`whitelist`), запрет неизвестных (`forbidNonWhitelisted`), преобразование типов (`transform`).
- Заголовки и политика контента через `helmet`.
- Ограничение размера тела: до 50 МБ (загрузка изображений).

## Frontend: разделы и потоки
- Маршруты:
  - `/login`, `/register` — аутентификация.
  - `/` → макет с дочерними маршрутами:
    - `dashboard` — главная панель.
    - `products` — каталог товаров.
    - `products/:id` — карточка товара.
    - `committees/:id` — детали комитета.
    - `reports` — отчеты (для менеджера/админа).
    - `settings` — настройки (категории, склады, комитеты, типы транзакций, статусы пользователей).
    - `audit-log` — журнал (только админ).
    - `users` — управление пользователями (только админ).
- Хранилища (Pinia):
  - authStore — аутентификация, роли, пользователь.
  - productsStore — список, текущий товар, фильтры, пагинация.
  - categoriesStore, warehousesStore, committeesStore — справочники.
  - salesStore, returnsStore — операции.
  - transactionTypesStore, userStatusesStore — справочники.
- UI: PrimeVue (Menubar, DataTable, Dialog, Toast, ConfirmDialog и др.), переключатель темы.
- Тесты: Vitest для ключевых представлений и стора.

## Реализовано (состояние)
- NestJS приложение с модулями: Auth, Users, Products, Categories, Sales, Returns, Warehouses, Committees, Transaction Types, User Statuses, Audit Log, MinIO, Prisma.
- Глобальная защита JWT и ролевой доступ.
- DTO‑валидация, CORS и заголовки безопасности.
- Каталог товаров: фильтры, поиск, сортировка, пагинация; загрузка и сжатие изображений; карточка товара с историей изменений.
- Операции продажи/возврата с аудитом и пересчетом остатков.
- Справочники: категории/склады/комитеты/типы транзакций/статусы пользователей.
- Журнал действий для администратора.
- Frontend на Vue 3: маршрутизация, состояние, компоненты, темы, тесты.

## Интерфейсы данных (общее)
- Пользователь: идентификатор, имя, логин/пароль (хеш), роль, статус.
- Товар: идентификатор, название, артикул (SKU), цена, категории, склад/комитет, изображения, остатки, атрибуты.
- Операции:
  - Продажа: товар, количество, цена/скидка, тип транзакции, пользователь, время.
  - Возврат: товар, количество, причина/тип, пользователь, время.
- Аудит: сущность, действие (create/update/delete/operation), изменения (поля «было/стало»), пользователь, IP, User‑Agent, время.

## Нефункциональные требования
- Производительность: отзывчивый UI, пагинация, минимизация трафика при изображениях (сжатие/превью).
- Безопасность: JWT, ролевая модель, CORS, Helmet, минимизация экспозиции данных.
- Масштабируемость: модульная архитектура; MinIO для файлов; Prisma для миграций.
- Тестируемость: покрытие ключевых сценариев (вход, каталог, операции).

## План доработок
- Документация API: добавить Swagger (описания DTO, схемы ошибок).
- Экспорт/импорт данных: CSV/XLSX для товаров/операций/отчетов.
- Расширенные отчеты: кастомные метрики, периодические выгрузки, сохраненные пресеты.
- Роли и права: более тонкая матрица разрешений на уровне операций и полей.
- Локализация: i18n, многоязычные метки категорий/типов транзакций.
- Наблюдаемость: health‑checks, метрики, централизованное логирование.
- UI/UX: улучшение доступности, быстрые действия, массовые операции в каталоге.
- Кэширование: клиентский кэш стора, серверные кэши для справочников.
- CI: линтинг/типизация/юнит‑тесты в пайплайне, предпросмотр.
- Безопасность: политики паролей, ограничение частоты входа, аудит входов/выходов.

## Критерии приемки
- Все текущие модули доступны согласно ролям и проходят валидацию.
- Товары создаются/редактируются/удаляются; изображения загружаются и отображаются.
- Операции продажи/возврата корректно изменяют остатки и пишут аудит.
- Отчеты загружаются, фильтры работают, таблицы и графики отображаются.
- Журнал действий показывает инициатора, время и набор изменений.
